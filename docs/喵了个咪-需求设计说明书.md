## 0. 阅读指南与关键假设

### 0.1 本文档解决什么问题

本文档是喵了个咪个人自托管版的唯一需求依据，覆盖产品范围、功能规则、数据模型、接口、Android 客户端、Go 服务端、权限隐私、验收与风险。任何范围或规则变更必须回写本文档。

### 0.2 关键假设

1. **小规模多用户**：单实例自托管，1 名管理员 + 少量普通用户（默认上限 50，可配置）；不做公开 SaaS、多租户、组织/团队。
2. **自托管**：Go 服务端运行在管理员自己的电脑、NAS 或树莓派上；数据只存在本机。
3. **数据库**：SQLite 单文件，WAL 模式；附件存本地目录；备份 = 数据库文件 + 附件目录。
4. **客户端**：第一阶段只做 Android；后续平台复用同一套 Flutter 代码。
5. **账号**：用户名 + 密码；管理员创建邀请码，用户凭邀请码注册；不收集手机号/邮箱。
6. **找回密码**：管理员生成一次性重置码，或在本机通过 CLI 重置；不做邮箱/短信自助找回。
7. **角色**：管理员管理用户与系统，但**默认不能查看其他用户的宠物隐私数据**，除非被共享。
8. **分享**：支持两种方式——分享给已注册用户（按用户名邀请），或生成访客链接/二维码（浏览器 H5 免登录）。
9. **提醒**：Android 本地通知；不接第三方推送服务。
10. **AI**：Android 客户端直连用户配置的模型厂商；API Key 仅存本机安全存储；服务端不接收、不代理 AI 请求。
11. **图片咨询（替代 OCR）**：当前版本不做端侧 OCR；用户可把化验单/症状照片作为图片消息发给支持视觉的模型，由模型直接解读。请求由客户端直连用户配置的模型，服务端不中转图片。
12. **网络**：优先局域网；远程访问推荐 Tailscale/WireGuard 或 HTTPS 反向代理；默认不直接暴露公网。
13. **扩展能力**：保留用户、宠物归属、成员授权、API 版本与数据库迁移；后续可从 SQLite 迁移到 PostgreSQL，增加邮件/推送/Web 管理端而不改领域模型。
14. **合规**：保护用户与访客的宠物健康数据；不采集与功能无关的个人信息。

### 0.3 优先级定义

| 优先级 | 含义 | 交付要求 |
| --- | --- | --- |
| P0 | MVP 必须 | 第一阶段必须完成 |
| P1 | 后续迭代 | 第一阶段后 1–2 个迭代完成 |

### 0.4 术语

| 术语 | 说明 |
| --- | --- |
| 管理员 | 首个账号，管理用户、邀请码、系统设置与备份；默认不查看他人宠物隐私 |
| 普通用户 | 通过邀请码注册的账号，拥有自己的宠物 |
| 宠物所有者 | 创建该宠物的用户，拥有该宠物的管理权 |
| 成员授权 | 宠物所有者邀请已注册用户共同照护的授权记录 |
| 设备 | 登录后绑定到某个用户的 Android 客户端 |
| 访客链接 | 宠物所有者生成的、免登录访问宠物信息的限时链接 |

| 档案 | 单只宠物的结构化信息 |
| 记录 | 疫苗、驱虫、体检、病历、体重等一次事件 |

| AI 服务商 | 用户自行配置的模型厂商，客户端直连 |

### 0.5 当前实现状态（2026-10-26）

第一阶段主闭环已实现并通过单元/接口/E2E 验证：账号与权限、宠物档案、健康记录、成长记录、预约、提醒、共享与访客 H5、AI 对话与边聊边记、离线只读、备份/恢复。

本版与早期设计的差异：

- **端侧化验单 OCR 已移除**：第 4.4 节与 OCR-001～008 仅保留为后续规划，当前版本不实现；化验单/症状照片以图片消息直接交给支持视觉的模型。
- **App 内语音按钮已移除**：语音输入统一使用系统输入法的语音功能，App 不申请麦克风权限。
- **新增成长记录**：每只宠物独立的成长时间线，支持手动记录与 AI 对话自动写入。
- **新增预约**：一次性照护计划，支持手动创建和 AI 对话创建（如“下周一要给手抓饼做个驱虫”）；与周期提醒一起进入照护提醒中心并共用本地通知；完成后自动生成关联健康记录，不影响周期规则。
- **边聊边记增强**：支持“记下吧”回溯上一条描述，按对话中的日期（如“10月5号”）归档；自动记录卡片可在 2 分钟内撤销，超时后按钮隐藏且不可撤销；共享只读宠物不自动写入；AI 不声称已写入，以绿色「已自动记录」卡片为准。
- **自建服务器地址**：登录页可设置独立部署的服务器地址（留空恢复默认）；设置后显示在「设置 → 服务器」。保存账号、Token、缓存、AI 会话与 AI Key 按服务器隔离，内置默认服务器沿用原有本地数据。
- **AI 配置迁移**：AI 服务设置支持以加密字符串导入/导出配置（AES-256-GCM + PBKDF2），密码不保存；导入时按服务商 ID 合并，保留当前已有配置。
- **应用图标**：使用 Noto 蓝色猫爪 emoji（U+1F43E，`#176BC6`），设计与资源见 `docs/logos/`。

尚未实现（后续迭代）：记录/宠物回收站 UI、通知栏内直接完成/稍后、访客操作审计 UI、症状图片识别、PDF 导出、成长相册、饮食/换药专用页面、完整离线写队列。

## 1. 产品概述

### 1.1 背景

养宠家庭常见问题：纸质疫苗本/病历易丢、驱虫疫苗节点易忘、网上建议不针对自家宠物、出差时无人照护。现有 App 多为云端多租户产品，数据不在自己手里，功能繁杂。本项目做一个**自己部署、自己掌控数据**的轻量工具。

### 1.2 产品定位

**一句话定位**：跑在自己服务器上的小规模多用户宠物档案 + AI 养宠助手 + 本地提醒 + 共享协作。

核心价值：

- **数据自持**：SQLite 文件 + 本地附件，备份就是复制文件。
- **多用户但轻量**：管理员 + 少量用户，邀请码注册，不做公开 SaaS。
- **一宠一档**：疫苗、驱虫、体检、病历、体重、照片统一管理。
- **档案驱动 AI**：AI 回答读取当前宠物档案，拒绝通用模板。
- **图片咨询**：化验单/症状照片直接发给支持视觉的模型解读；当前版本不做端侧 OCR。
- **共享协作**：可分享给已注册用户共同照护，也可生成免登录访客链接。
- **本地提醒**：不依赖推送服务，App 关闭也能收到系统通知。
- **可扩展**：用户、宠物归属、成员授权、API 版本与迁移保留，后续可换 PostgreSQL 或增加 Web 管理端。

### 1.3 成功标准

| 维度 | 标准 |
| --- | --- |
| 功能 | 第一阶段 P0 验收通过率 100% |
| 设备 | Android 10–16 主流机型可安装、注册/登录、完成主流程 |
| 质量 | 崩溃率 < 0.1%，ANR < 0.05% |
| 性能 | 冷启动 P90 ≤ 2.0 s；本地列表首屏 ≤ 500 ms |
| 图片咨询 | 图片消息可发给支持视觉的模型；未启用视觉时有明确提示 |
| 提醒 | 杀进程后本地提醒仍可触发 |
| 备份 | 一条命令完成备份与恢复 |
| UAT | 20 名真实用户主流程完成率 ≥ 90% |

### 1.4 范围

**第一阶段（Android MVP）**

- 管理员初始化、邀请码、用户注册/登录、设备配对、设备管理；
- 多宠档案、电子身份证卡预览；
- 疫苗/驱虫/体检/病历/体重/附件/时间线；
- 成长记录：每只宠物独立的成长时间线，支持手动与 AI 对话写入；
- AI 会话：多厂商 Key、流式回答、档案上下文、风险分级、图片消息、输入法语音、对话式记录；
- 本地提醒：疫苗/驱虫/体检/生日，完成写回；
- 共享协作：分享给已注册用户（成员授权）+ 访客链接 H5；
- 设置、备份/恢复、导出、隐私说明。

**后续阶段**

- HarmonyOS / iOS / PC / Web；
- 成长相册、饮食/换粮、百科；
- 端侧化验单 OCR 与结构化草稿（当前版本已移除）；
- 多页 OCR、症状图片识别；
- 电子证件 PDF 导出、服务卡片。

**不做**

- 公开注册、邮箱/短信找回、Web 管理后台、多租户/组织/团队；
- 云数据库、对象存储、第三方推送、邮件服务；
- 在线问诊、处方、药品售卖、保险、社交社区；
- 智能硬件接入。

### 1.5 成功路径

1. 服务器本机初始化管理员密码 → 生成邀请码。
2. 用户在 Android 注册（邀请码）→ 登录 → 绑定设备 → 设置宠物档案。
3. 日常记录/图片咨询 → 自动生成提醒。
4. 提问 AI → 结合档案回答 → 可转成记录草稿。
5. 分享给已注册用户，或生成访客链接 → 家人查看/完成照护。
6. 管理员管理用户与备份，定期备份 SQLite 与附件目录。

## 2. 用户与场景

### 2.1 角色

| 角色 | 说明 | 权限 |
| --- | --- | --- |
| 管理员 | 首个账号，管理用户/邀请码/系统/备份 | 用户与系统管理；默认不读取他人宠物隐私 |
| 普通用户 | 邀请码注册 | 管理自己的宠物，邀请他人共享 |
| 宠物所有者 | 创建该宠物的用户 | 该宠物全部权限 |
| 共同照护者 | 被邀请的注册用户，或访客链接 | 查看摘要/提醒、完成提醒、新增照护记录/体重、上传照片 |
| 只读访客 | 被邀请的注册用户，或访客链接 | 查看宠物摘要、照护说明、提醒 |

> 注册用户通过"成员授权"加入；访客通过"访客链接"加入。两者权限相同，但身份与撤销方式不同。

### 2.2 关键旅程

**A. 首次部署、邀请与配对**

1. 在电脑/NAS 运行 `mypet init` 设置管理员密码。
2. 管理员登录 App，创建邀请码。
3. 新用户凭邀请码注册用户名/密码。
4. 用户登录后绑定设备（扫码/配对码）。
5. 进入首页，创建第一只宠物。

**B. 记录与提醒**

1. 新增体内驱虫记录（日期、药品、剂量、体重）。
2. 系统按周期计算下次到期日。
3. Android 本地调度提醒；到期通知可"已完成/稍后"。
4. 完成时写回记录并重算下次。

**C. AI 与图片咨询**

1. 配置模型厂商与 API Key（仅本机）。
2. 提问"咪咪今天软便怎么办" → 客户端组装档案上下文 → 流式回答。
3. 发一张化验单/症状照片 → 支持视觉的模型直接解读 → 回答中提示是否需要写入记录。

**D. 共享协作**

1. 宠物所有者选择"分享给用户"，按用户名邀请已注册用户，设置只读/共同照护。
2. 对方登录后在宠物列表看到"共享"标识，可查看/完成提醒/新增照护记录。
3. 或创建"访客链接"（7 天有效、可选口令），家人打开 H5 免登录查看/打卡。
4. 所有者可移除成员或撤销链接，立即失效。

## 3. 架构与信息架构

### 3.1 架构

```
┌──────────────────── Android App（Flutter）────────────────────┐
│ 档案 │ 记录 │ AI 会话 │ 提醒 │ 共享协作 │ 设置 │ 用户管理*      │
├───────────────────────────────────────────────────────────────┤
│ 本地缓存（Drift/SQLite） │ 安全存储 │ 本地通知 │ 相机（语音走输入法）│
└───────────────────────────────┬───────────────────────────────┘
                                │ HTTP/JSON（局域网或 Tailscale）
┌───────────────────────────────▼───────────────────────────────┐
│                     Go 单二进制服务端                          │
│ 认证/用户/设备 │ 宠物/记录 │ 提醒 │ 成员授权/访客链接 │ 附件 │ H5 │
├───────────────────────────────────────────────────────────────┤
│ SQLite 文件（WAL） │ 本地附件目录 │ 备份/恢复 CLI               │
└───────────────────────────────────────────────────────────────┘
                                │ 客户端直连（用户 Key）
                     ┌──────────▼──────────┐
                     │ AI 模型厂商          │
                     └─────────────────────┘
```

- 服务端是唯一数据源；Android 只做读缓存和短时离线。
- 不做云同步、消息队列、推送服务、对象存储。
- 访客 H5 由 Go 服务端内嵌提供，不依赖 Flutter Web。

### 3.2 页面地图

```
Android
├─ 登录/注册（邀请码）→ 绑定设备
├─ 首页（待办、宠物卡片、快捷入口）
├─ 档案（列表 → 详情 → 基础信息/记录/体重/证件卡）
├─ 记录（疫苗/驱虫/体检/病历/体重/附件）
├─ 成长（时间线 → 新增记录）
├─ AI（会话列表 → 对话 → 输入法语音/图片 → 记录草稿）
├─ 提醒（列表 → 完成/稍后/跳过）
├─ 共享（成员邀请 / 访客链接 / 撤销）
├─ 用户管理（仅管理员：用户、邀请码、重置密码）
└─ 设置（服务器、设备、AI 服务、备份、关于）

访客 H5（/g/{token}）
├─ 宠物摘要与照护说明
├─ 今日待办/提醒
├─ 完成打卡与拍照反馈
└─ 口令校验/失效提示
```

### 3.3 交互原则

- 一屏一事；核心任务不超过 3 步。
- 所有列表具备加载、空、错误、离线状态。
- 删除/撤销/恢复需二次确认。
- 访客页面只展示照护必需信息，默认不展示完整病历。
- AI 生成内容明确标识，医疗建议必须带免责声明。

## 4. 功能需求

### 4.1 账号、设备与权限（ACC）

| 编号 | 需求 | 优先级 | 验收要点 |
| --- | --- | --- | --- |
| ACC-001 | 管理员初始化 | P0 | 服务端 `mypet init` 创建首个管理员账号；仅在未初始化时可用 |
| ACC-002 | 邀请码 | P0 | 管理员创建邀请码（有效期、使用次数）；默认用户上限 50，可配置 |
| ACC-003 | 用户注册 | P0 | 用户名 4–20 位、唯一；密码 8–32 位；必须携带有效邀请码；无手机号/邮箱 |
| ACC-004 | 登录与设备绑定 | P0 | 用户名+密码登录；登录后绑定设备 Token；连续 5 次失败锁定 15 分钟 |
| ACC-005 | 设备管理 | P0 | 用户查看/吊销自己的设备；管理员可查看所有设备并吊销 |
| ACC-006 | 修改密码 | P0 | 需旧密码；修改后该用户其他设备 Token 失效 |
| ACC-007 | 密码重置 | P0 | 管理员生成一次性重置码（15 分钟）或本机 CLI 重置；重置后该用户全部设备下线 |
| ACC-008 | 用户管理 | P0 | 管理员可查看用户列表、禁用/启用、重置密码、查看最后登录 |
| ACC-009 | 管理员权限边界 | P0 | 管理员默认不能读取其他用户的宠物/记录，除非被共享；不得 impersonation |
| ACC-010 | 用户数据隔离 | P0 | 每个用户只能访问自己拥有的宠物、被共享的宠物、自己创建的记录 |
| ACC-011 | 账号注销 | P1 | 管理员可删除用户；删除前需转移或删除其宠物；操作留痕 |
| ACC-012 | 退出/清除本机数据 | P1 | 退出清除设备 Token 与缓存；不影响服务器数据 |

**规则**

- 注册为邀请制，不开放公开注册；邀请码一次性/限次使用，过期作废。
- 用户名全局唯一、不区分大小写；密码 Argon2id 哈希；日志不得出现明文。
- 首个账号为管理员；后续可增加管理员（P1），但 MVP 只保留一个管理员。
- 设备 Token 哈希存储；吊销/改密/重置后立即失效。
- 所有宠物/记录接口必须校验：所有者、`PetMember` 成员授权、或访客 `ShareGrant`。
- 管理员默认只能看到用户列表与账号状态，不能查看其宠物隐私；需要排障时由用户主动共享。
- 未来扩展：`User.role`、`PetMember`、`ShareGrant` 保留多管理员/更多角色能力。

### 4.2 宠物档案（PET）

| 编号 | 需求 | 优先级 | 验收要点 |
| --- | --- | --- | --- |

- 删除宠物 30 天内可恢复；到期物理删除数据库记录与附件。
- 同一宠物名可重复，列表用头像/品种区分。
- 管理员默认看不到用户宠物，除非用户主动共享。

### 4.4 端侧化验单 OCR（已移除，后续规划）

> 当前版本不实现本节；化验单/症状照片以图片消息直接交给支持视觉的模型。以下条目保留作为后续规划。

| 编号 | 需求 | 优先级 | 验收要点 |
| --- | --- | --- | --- |
| OCR-001 | 拍照/选图 | P0 | 支持相机、相册；裁剪/旋转 |
| OCR-002 | 端侧识别 | P0 | Android 端侧中文 OCR，单页 ≤ 3 s |
| OCR-003 | 结构化 | P0 | 输出医院、日期、指标、数值、单位、参考范围、异常标记 |
| OCR-004 | 草稿确认 | P0 | 低置信高亮、逐项编辑；未确认不写入 |
| OCR-005 | 写入记录 | P0 | 确认后写入体检/化验记录并保留原图 |
| OCR-006 | 降级 | P0 | OCR 失败 → 视觉模型；仍失败 → 手动表单 + OCR 文本参考 |
| OCR-007 | 隐私 | P0 | 端侧识别不上传图片；云端视觉需单独同意 |

**流程**

1. 拍照/选图 → 裁剪/旋转/去反光提示。
2. 端侧 OCR（ML Kit bundled Chinese 或 PaddleOCR Lite，S0 选型）。
3. OCR 文本（模型支持视觉时附图片）交给用户配置的模型，按 JSON Schema 输出字段。
4. 生成草稿卡：异常项高亮、低置信字段标记。
5. 用户确认 → 写入体检/化验记录 → 保留原图。
6. 解析失败 → 手动表单，保留 OCR 文本。

**规则**

- 不自动写入；不做诊断结论；异常项仅提示"超出参考范围"。
- 化验数值不进入日志/埋点。
- 单页为 MVP；多页 P1。

## 5. 关键业务规则

### 5.1 年龄与生命阶段

- 年龄 = 当前日期 − 生日；不足 1 岁显示月，不足 1 月显示天。
- 仅知估算年龄标记"约"，不参与精确疫苗周期。
- 生命阶段阈值由服务端配置，客户端展示。

### 5.2 提醒优先级

- 同一天：疫苗 > 驱虫 > 体检 > 洗护 > 生日。
- 同一时刻合并为一条通知（"今天有 3 项待办"）。
- 免打扰时段顺延，不丢失。

### 5.3 AI 安全

- 禁止：确诊、处方、具体剂量、人用药替代、安乐死建议。
- 必须：风险级别、就医红线、免责声明。
- 客户端本地红线词库 + 系统提示词 + 输出后处理；L3 卡独立展示。
- AI 回答标注"AI 生成，仅供参考"。

### 5.4 图片与 OCR 规则（当前版本不做端侧 OCR）

- 图片消息由客户端直连支持视觉的模型；服务端不中转图片。
- 不做诊断；异常仅提示超出参考范围。
- AI 解读仅供参考，写入记录必须经用户确认。
- 当前版本不生成 OCR 草稿，也不在端侧保存识别结果。

### 5.5 共享权限

| 能力 | 宠物所有者 | 共同照护者（注册/访客） | 只读（注册/访客） |
| --- | --- | --- | --- |
| 查看宠物摘要 | ✓ | ✓ | ✓ |
| 查看完整病历 | ✓ | 注册用户 ✓ / 访客 ✗ | ✗ |
| 查看提醒 | ✓ | ✓ | ✓ |
| 完成提醒 | ✓ | ✓ | ✗ |
| 新增照护记录/体重 | ✓ | ✓ | ✗ |
| 编辑/删除自己新增的记录 | ✓ | ✓ | ✗ |
| 上传照片 | ✓ | ✓ | ✗ |
| 编辑疫苗/病历 | ✓ | ✗ | ✗ |
| 创建/撤销分享 | ✓ | ✗ | ✗ |
| 删除宠物/备份/导出 | ✓ | ✗ | ✗ |

- 管理员默认不在上述权限内：不能读取用户宠物，除非被用户主动共享。
- 宠物所有者可随时移除成员/撤销链接；立即生效。
- 注册成员与访客权限相同，但注册成员有账号、可多设备登录；访客只有链接。
- 访客不能再次分享。
- 访客操作记录 `grantId` 与时间。

### 5.6 数据保留与备份

| 数据 | 策略 |
| --- | --- |
| 宠物/记录 | 软删除 30 天，到期物理删除 |
| 附件 | 随记录删除；备份保留 |

## 8. 接口需求

### 8.1 约定

- 基础路径 `/api`；JSON over HTTP/HTTPS。
- 用户/设备：`Authorization: Bearer <deviceToken>`；设备 Token 关联 `userId`。
- 管理员：同一 Token + 服务端校验 `isAdmin`；管理员接口不能读取用户宠物数据。
- 访客：`/g/{token}` H5 + `/api/guest/{token}/...`，可选 `X-Share-Passcode`。

- 统一响应：`{ code, message, data, requestId }`。
- 错误码：`1xxxx` 参数、`2xxxx` 鉴权、`3xxxx` 业务、`4xxxx` 限流、`5xxxx` 服务端。

### 8.3 注册、登录与设备

1. 管理员 `mypet init` 创建首个账号。
2. 管理员在 App 创建邀请码。
3. 新用户 `POST /api/auth/register`（用户名、密码、邀请码）。
4. 用户 `POST /api/auth/login`，服务端创建设备记录并返回设备 Token（仅返回一次）。
5. Android 将 Token 存入 Keystore；后续请求带 `Authorization`。
6. 改密/重置/禁用/吊销设备后，相关 Token 立即失效。

### 8.4 访客 Token

- 创建：服务端生成 128 位随机 Token，返回一次性明文，仅存哈希。
- 访问：`/g/{token}` 或 `/api/guest/{token}/...`。
- 可选口令：请求头 `X-Share-Passcode`；连续 5 次错误锁定 10 分钟。
- 撤销/过期：服务端立即拒绝。
- 不在 URL 中放宠物 ID；不记录完整 Token 日志。

## 10. Go 服务端技术方案

| 层面 | 选型 |
| --- | --- |
| 语言 | Go 1.24+ |
| 路由 | chi |
| 数据库 | SQLite（modernc.org/sqlite，纯 Go） |
| SQL | sqlc（类型安全查询） |
| 迁移 | goose |
| 配置 | YAML + 环境变量 |
| 日志 | slog（结构化 JSON） |

| 部署 | 单二进制 + systemd/Docker |
| 备份 | `mypet backup` / `mypet restore` |

**SQLite 设置**

- `journal_mode=WAL`、`busy_timeout=5000`、`foreign_keys=ON`、`synchronous=NORMAL`。
- 单写者；写事务短小；避免长事务；默认最多 50 用户，适合小规模自托管。
- 所有查询强制带用户/成员/访客授权条件，禁止只按 `petId` 查询。
- 启动时自动迁移；备份使用 `VACUUM INTO`。
- 若用户量/并发增长，可迁移 PostgreSQL；领域模型与 API 不变。

**CLI**

```
mypet init                  # 创建管理员账号
mypet serve                 # 启动服务
mypet create-invite         # 生成邀请码（也可在 App 内操作）
mypet reset-password <user> # 本机重置指定用户密码
mypet backup --out backup/  # 备份数据库+附件
mypet restore --from ...    # 恢复
mypet doctor                # 检查数据库/附件/权限
```

**部署**

- 默认监听 `0.0.0.0:8787`；局域网访问。
- 公网：Caddy/Nginx 反代 + HTTPS，或 Tailscale/WireGuard。
- 数据目录 `data/` 权限 0700；数据库/附件仅服务账户可读。
- 单二进制支持 Windows/macOS/Linux；Docker 可选。

## 13. 风险与待确认

### 13.1 风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 服务端暴露公网 | 数据泄露 | 默认局域网；公网必须 HTTPS/Tailscale；强密码；限流 |
| SQLite 并发/损坏 | 数据丢失 | WAL、单写者、短事务；默认上限 50 用户；定期备份、恢复演练 |
| 多用户越权 | 数据泄露 | 每个查询强制 owner/member/grant 条件；接口测试覆盖越权 |
| 管理员越权 | 用户隐私泄露 | 管理员只看账号状态；不提供宠物查询接口；审计 |
| 邀请码/重置码泄露 | 非法注册/账号被盗 | 一次性、限时、限次、限流、审计 |
| 备份缺失 | 数据丢失 | CLI 备份、启动提示、文档说明 |
| Android 后台限制 | 提醒不触发 | AlarmManager/WorkManager；厂商白名单引导 |
| 图片解读准确率 | 模型误读 | 提示仅供参考；异常建议就医；不写诊断 |
| 访客链接泄露 | 隐私风险 | 短时效、口令、撤销、限流、最小化 |
| AI 幻觉/越界 | 合规与信任 | 本地红线词库、L3 固定卡、免责声明、兽医审核 |
| 小团队维护 | 迭代慢 | 控制范围、优先 P0、自动化测试 |

### 13.2 已确认决策

| 决策 | 结论 |
| --- | --- |
| 用户规模 | 默认上限 50，可配置；MVP 只保留 1 个管理员 |
| 注册方式 | 邀请码自助注册（用户名 + 密码） |
| 密码重置 | 管理员生成一次性重置码（15 分钟有效），服务器 CLI 作为兜底 |
| 共享方式 | 同时保留"注册用户成员授权"与"免登录访客链接"两种方式 |
| 技术栈 | Go 单二进制 + SQLite 文件 + 本地附件目录 |

### 13.3 待确认

1. 服务端主要运行环境：Windows 电脑、NAS 还是树莓派？影响打包与自启方式。
2. 远程访问是否统一用 Tailscale，还是需要域名 + HTTPS 反代？
3. 图片消息的单图大小、数量与视觉模型开关策略？
4. 共同照护者是否允许新增体重/照护记录，还是只读+完成提醒？
5. 是否需要导出 PDF 证件卡，还是第一阶段只做截图分享？
6. 备份是否要求应用内触发，还是只用 CLI？
7. 未来迁移 PostgreSQL / 增加 Web 管理端的触发条件是什么？
