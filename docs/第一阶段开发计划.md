# 喵了个咪 · 小规模多用户自托管版第一阶段开发计划

| 项目 | 内容 |
| --- | --- |
| 文档版本 | V2.3 |
| 日期 | 2026-10-26 |
| 依据 | 《喵了个咪-需求设计说明书》V3.3 |
| 阶段定位 | 第一阶段：Android 单端 MVP（小规模多用户自托管） |
| 平台范围 | Android |
| 服务端 | Go 单二进制 + SQLite 文件 + 本地附件目录 |
| 周期 | 12 周开发（W1–W12）+ 2 周缓冲 |
| 团队规模 | 建议 5 人 |

> **执行状态（2026-10-26）**：第一阶段主闭环已实现，并通过 Go 单测、Flutter 分析和端到端 E2E。端侧 OCR 已移除，改为图片消息直连视觉模型；App 内语音按钮已移除，改用系统输入法语音。文中 OCR 相关条目仅作历史规划，发布清单按实际状态更新。

---

## 1. 阶段目标

### 1.1 一句话目标

用 12 周做出可安装、可体验的 Android MVP：管理员初始化并发放邀请码，用户注册/登录，管理自己的宠物，完成「建档 → 记录 → 图片咨询 → 本地提醒 → AI 会话/对话式记录」，并可分享给注册用户或访客链接共同照护。

### 1.2 成功标准

| 维度 | 标准 |
| --- | --- |
| 功能 | 本阶段 P0 需求验收通过率 100% |
| 设备 | Android 10–16 主流机型可安装、注册/登录、完成主流程 |
| 服务端 | Go 单二进制在 Windows/macOS/Linux 至少各验证 1 台；SQLite 可备份/恢复 |
| 多用户 | 默认 50 用户上限；用户数据隔离；管理员不能读取用户宠物 |
| 质量 | 崩溃率 < 0.1%，ANR < 0.05% |
| 性能 | 冷启动 P90 ≤ 2.0 s；本地列表首屏 ≤ 500 ms |
| 图片咨询 | 图片消息可发给支持视觉的模型；未启用视觉时有明确提示 |
| 提醒 | 杀进程后本地提醒仍可触发 |
| 备份 | 一条 CLI 命令完成备份与恢复 |
| UAT | 20 名真实用户主流程完成率 ≥ 90% |

### 1.3 本阶段范围（P0）

| 模块 | 本阶段交付 |
| --- | --- |
| 管理员与账号 | 管理员初始化、邀请码、用户注册/登录、设备管理、改密/重置码 |
| 用户管理 | 用户列表、禁用/启用、重置密码；管理员不读取用户宠物 |
| 宠物档案 | 多宠建档、基础信息、电子身份证卡预览、归属标识 |
| 健康记录 | 疫苗、驱虫、体检、病历、体重、附件、时间线 |
| 成长记录 | 每只宠物独立成长时间线，手动记录与 AI 对话写入 |
| 图片咨询 | 化验单/症状照片作为图片消息交给支持视觉的模型；不做端侧 OCR |
| AI | 多厂商 API Key、连接测试、档案上下文、流式回答、风险分级、输入法语音、对话式记录 |
| 提醒 | 疫苗/驱虫/体检/生日、本地通知、完成/稍后/跳过、写回 |
| 共享 | 分享给注册用户（成员授权）+ 访客链接/H5、角色、撤销 |
| 基础 | SQLite、本地缓存、备份/恢复、设置、隐私说明 |

### 1.4 明确不在本阶段

- HarmonyOS、iOS、PC、Web；
- 公开注册、邮箱/短信找回、Web 管理后台、多租户/组织/团队；
- 云数据库、对象存储、第三方推送、邮件服务、Redis/消息队列；
- 症状图片识别、多页/批量 OCR；
- 成长相册、饮食/换粮、日常打卡、百科；
- 电子证件 PDF 导出、服务卡片；
- 完整离线写队列（只做只读缓存，写队列 P1）。

### 1.5 已确认决策

| 决策 | 结论 |
| --- | --- |
| 用户规模 | 默认上限 50，可配置 |
| 注册方式 | 邀请码自助注册 |
| 密码重置 | 管理员生成一次性重置码（15 分钟） |
| 共享方式 | 注册用户成员授权 + 免登录访客链接并存 |
| 技术栈 | Android + Go 单二进制 + SQLite 本地文件 |

## 2. 团队与协作

### 2.1 建议团队配置

| 角色 | 建议人数 | 主要职责 |
| --- | --- | --- |
| 产品/设计 | 1 | 范围、流程、线框、视觉、OCR/共享页面、验收 |
| Flutter/Android | 2 | App 页面、缓存、通知、相机/麦克风、OCR、AI、共享 |
| Go 服务端 | 1 | HTTP API、SQLite、用户/权限、附件、H5、CLI、备份 |
| QA | 1 | 用例、真机、接口/越权测试、UAT |
| DevOps/安全 | 0.3 | 打包、签名、部署、Tailscale/HTTPS、安全检查 |

### 2.2 技术栈

| 层面 | 选型 |
| --- | --- |
| Android | Flutter + Dart、Riverpod、go_router、Drift、dio |
| 本地安全存储 | flutter_secure_storage（Keystore） |
| 通知 | flutter_local_notifications + AlarmManager/WorkManager |
| OCR | ML Kit bundled Chinese 或 PaddleOCR Lite（S0 选型） |
| AI | 自定义 AiProviderAdapter，直连厂商 |
| 服务端 | Go 1.24+、chi、sqlc、goose |
| 数据库 | SQLite（modernc.org/sqlite，WAL） |
| 附件 | 本地 `data/uploads` |
| H5 | Go `embed` 内嵌访客页面 |
| 部署 | 单二进制 + systemd/Docker；Tailscale/HTTPS 可选 |

> 不引入 Redis、PostgreSQL、对象存储、邮件服务、推送服务或 Web 管理后台。

### 2.3 协作机制

- 每日 15 分钟站会。
- 每周一次需求/设计/接口评审。
- 每两周一次 Sprint 评审 + 回顾。
- 每个门禁（G0–G5）产品、Android、Go、QA 共同签字。
- 需求变更回写文档，口头变更不进入开发。

## 5. 分阶段计划

### S0：设计与 PoC（W1–W2）

**目标**：确认产品方案、API/数据模型与 Android/OCR/Go 技术可行性。

**产品/设计**

- 页面流程、关键状态、核心页面线框与视觉。
- 注册/登录、用户管理、OCR 结果页、共享/H5、配对流程设计。
- 验收用例初稿。

**技术**

- Android：Flutter 工程、相机/相册、麦克风、本地通知、安全存储。
- Go：单二进制 Demo、SQLite WAL、迁移、附件上传、H5 embed。
- OCR：30–50 张脱敏中文化验单，对比 ML Kit bundled Chinese 与 PaddleOCR Lite。
- AI：至少 2 家 OpenAI 兼容厂商流式请求与错误码。
- 输出 API 契约（OpenAPI/手写文档）与 SQLite schema。

**交付物**

- 交互/视觉稿、设计 Token。
- API 契约、SQLite schema、错误码。
- Android/OCR/Go PoC 报告与风险清单。

**G0 门禁**

- Android PoC 可运行；Go Demo 可启动并读写 SQLite。
- OCR 主引擎选定，关键字段准确率达到约定阈值（建议 ≥ 85%）。
- API 契约/schema 评审通过，估算校准。

---

### S1：账号、权限与宠物（W3–W5）

**目标**：建立多用户底座，用户能注册、登录、管理自己的宠物。

**Go 服务端**

- `init/serve/create-invite/reset-password` CLI。
- SQLite schema、goose 迁移、WAL/外键/busy_timeout。
- 管理员账号、邀请码、注册、登录、设备 Token、设备吊销。
- 用户列表、禁用/启用、密码重置码。
- 宠物 CRUD、电子身份证号生成、归属校验。
- 结构化日志、错误码、限流。

**Android**

- 首次管理员登录/初始化引导。
- 邀请码注册、用户名/密码登录。
- 设备 Token 安全存储；首页空状态。
- 宠物列表、建档/编辑、归属标识。
- 网络层与错误/离线状态。

**交付物**

- 管理员创建邀请码；新用户注册登录。
- 用户只能看到自己的宠物。
- 设备列表与吊销可用。

**G1 门禁**

- 管理员/邀请码/注册/登录闭环。
- 用户 A 无法访问用户 B 未共享的宠物。
- 管理员能看到用户列表，但看不到用户宠物。
- 宠物建档/编辑/删除/恢复正确。

---

### S2：记录与 OCR（W6–W7）

**目标**：完成宠物健康记录与拍照入库。

**Android**

- 疫苗/驱虫/体检/病历/体重记录表单。
- 附件拍照/相册、压缩、EXIF 清理、上传重试。
- 时间线、类型筛选、体重曲线。
- OCR 拍照/裁剪 → 端侧识别 → 草稿卡 → 确认写入。
- 低置信字段高亮；失败降级手动表单。

**Go 服务端**

- 记录 CRUD、体重、附件、时间线接口。
- 文件白名单、大小限制、路径穿越防护。
- 记录与附件的一致性（事务/清理）。
- 成员/所有者权限校验。

**交付物**

- 记录全类型可新增/编辑/删除/恢复。
- 单页化验单可 OCR 并写入体检记录。
- 原图与记录关联保存。

**G2 门禁**

- 建档→记录→附件→时间线完整可用。
- OCR 草稿未确认不写入；确认后数据正确。
- 删除记录/附件不残留孤儿文件。
- 共同照护者只能操作被授权宠物的记录。

---

### S3：AI、语音与提醒（W8–W9）

**目标**：AI 能结合档案回答问题，记录能驱动本地提醒。

**AI**

- 服务商设置、Key 安全存储、连接测试、错误码。
- 流式会话、取消/重试、会话历史。
- 档案上下文组装、多宠识别、L3 风险卡、免责声明。
- 语音转文字、编辑后发送、失败降级。
- 对话式记录草稿与确认写入。

**提醒**

- 疫苗/驱虫/体检/生日规则计算。
- Android 本地通知调度；完成/稍后/跳过。
- 完成后写回记录并重算下次。
- `occurrenceKey` 去重；共享成员提醒。

**交付物**

- 至少 2 家厂商可配置并流式对话。
- 语音输入可用。
- 记录→提醒→完成→写回闭环。

**G3 门禁**

- 未配置 Key 不请求；Key 仅本机、按用户隔离、重启可用。
- L3 红旗词必出就医卡；回答不给剂量。
- 杀进程后本地提醒仍触发。
- 对话式记录未确认不写入，确认后提醒正确。

---

### S4：共享与设置（W10–W11）

**目标**：用户能分享给注册用户或访客，所有者能管理设备与备份。

**共享**

- 宠物所有者按精确用户名邀请注册用户，设置只读/共同照护。
- 成员列表、移除、立即失效。
- 创建访客链接：有效期、口令、二维码。
- Go 内嵌 H5：宠物摘要、照护说明、今日待办、完成打卡、拍照反馈。
- 数据最小化：默认不展示完整病历；访客操作记录。

**设置**

- 服务器状态、设备管理、密码修改/重置码。
- 用户管理（管理员）：用户列表、禁用/启用、邀请码。
- 备份/恢复 CLI 与 App 内说明。
- 导出、清理缓存、关于、隐私说明。

**交付物**

- 注册用户被邀请后可见共享宠物。
- 访客免登录打开 H5 并完成照护。
- 移除成员/撤销链接立即失效。
- 备份/恢复可用。

**G4 门禁**

- 只读/共同照护权限正确。
- 用户 A 不能访问未共享的用户 B 宠物。
- 管理员不能读取用户宠物。
- 备份后恢复数据完整。

---

### S5：联调与发布（W12）

**目标**：达到可安装试用的质量。

**工作内容**

- Android 全链路联调：管理员→邀请码→注册→登录→建档→记录→OCR→AI→提醒→共享。
- 性能：冷启动、列表、图片、OCR、AI 流式。
- 异常：断网、服务器不可达、Token 失效、权限拒绝。
- 越权测试：用户隔离、成员权限、管理员边界、访客 Token。
- 真机矩阵：Android 10–16、主流厂商、折叠屏、大字体。
- UAT：20 名真实用户。
- 隐私说明、权限说明、AI/医疗免责声明。
- 签名、打包、发布说明、备份演练。

**交付物**

- Android Release APK/AAB 与签名。
- 测试报告、UAT 报告、性能报告、OCR 准确率报告。
- 部署与备份文档。

**G5 门禁**

- P0 验收通过，无阻塞缺陷。
- 崩溃/ANR/性能达标。
- 账号/权限/备份/共享撤销验证通过。
- UAT 完成率 ≥ 90%。

## 9. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 多用户越权 | 数据泄露 | 每个查询强制 owner/member/grant 条件；越权测试；代码评审 |
| 管理员越权 | 用户隐私泄露 | 管理员只看账号状态；不提供宠物查询接口；审计 |
| 邀请码/重置码泄露 | 非法注册/账号被盗 | 一次性、限时、限次、限流、审计 |
| 本地服务暴露公网 | 数据泄露 | 默认局域网；公网用 Tailscale/WireGuard 或 HTTPS 反代；强密码/限流 |
| SQLite 并发/损坏 | 数据丢失 | WAL、单写者、短事务、默认 50 用户、定期备份 |
| 备份缺失 | 数据丢失 | CLI 备份、启动提示、文档、每周提醒 |
| Android 后台限制 | 提醒不触发 | AlarmManager/WorkManager；厂商白名单引导；应用内红点 |
| OCR 准确率/版式 | 识别错误 | 样本集选型；端侧+视觉模型；低置信高亮；用户确认 |
| 访客链接泄露 | 隐私风险 | 短时效、口令、撤销、限流、数据最小化 |
| AI 厂商差异 | 体验不一致 | 适配器抽象；OpenAI 兼容优先；错误码统一 |
